# Coherent assistant instructions

Revise the full instruction text under the [behavior-driven contract](../specs/2026-10-14-behavior-driven-tools.md), using the [natural-player failures](../validation/2026-10-15-natural-player-workflow-fixes.md) as acceptance cases. Keep tool APIs and live readers unchanged.

The current text accumulates warnings without stating the evidence needed for a decision. It mixes search completeness with record completeness, requires container discovery even when inspected materials already suffice, discourages cheapest-route claims without defining bounded comparisons, and requests exact rereads without acknowledging that extraction limits may persist. These are instruction-design defects; they are not proof of the model's internal cause of failure.

Replace the text with an ordered policy: understand the goal; establish current evidence and its scope; verify prerequisites for a recommendation; investigate the specific remaining gap; answer with an actionable result and explicit conditions. Define different proof requirements for sufficient materials, missing materials and optimization. A partial search can contain a complete usable recipe, while a complete search can contain an incomplete recipe. Positive feasibility requires every necessary ingredient and operational constraint; partial ingredient totals never establish affordability. Unknown containers prevent broad absence claims but do not invalidate sufficient materials already verified.

Preserve source authority, live reads, reference/cursor identity, visual targeting, citations, history trust, navigation, privacy and read-only boundaries. Keep tool mechanics together, avoid prescribing an exhaustive sequence, and permit a different source or recipe when a bounded exact read cannot resolve the gap. Use ordinary player wording in answers.

Commit the rewrite and updated changelog immediately. Replace tests tied to obsolete sentence wording with request-assembly checks; string presence cannot validate model reasoning. Run automated tests/build and an independent coherence review. Record review and build evidence separately from model acceptance. The existing hopper failure remains open until a new installed-build conversation verifies complete recipe accounting, relevant carried materials and a feasible plan. Do not label the rewrite a demonstrated behavioral fix based on compilation or prompt inspection.
