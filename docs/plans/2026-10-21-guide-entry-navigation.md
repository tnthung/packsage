# Guide Entry Navigation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clicking a Modonomicon, GuideME, Immersive Engineering or Actually Additions citation opens that entry, page or heading in the mod's own viewer. Saved links keep working across reconnects, reloads and Minecraft restarts.

**Architecture:** Each of the four readers overrides the existing `GuideDocumentReader` hooks `navigationTargets`, `refreshNavigation` and `open`. `GuideDocumentProvider` already runs these hooks on the client executor with scope guards. A new fragment-aware `navigationTargets` overload lets GuideME derive heading anchors from the cited fragment. Each reader receives a package-private opener seam holding the client-thread check and the native open call; tests replace it with a recording fake.

**Tech Stack:** Java 21, Minecraft 1.21.1, NeoForge 21.1.202, Modonomicon compile API (1.120.4), reflective GuideME, Immersive Engineering and Patchouli access, JUnit 5, Gradle 8.11.1.

**Spec:** [Guide entry navigation](../specs/2026-10-21-guide-entry-navigation.md). Research: [guide entry navigation APIs](../research/2026-10-21-guide-entry-navigation.md). Parent contract: [persistent source navigation](../specs/2026-10-18-persistent-navigation.md).

## Global Constraints

- Keep `Evidence.NavigationTarget(scope, providerId, sourceHandle, targetId)`, the serialized conversation format and the model tool schemas unchanged.
- Durable `targetId` formats are exactly:
  - Modonomicon: `bookId|entryId`
  - GuideME: `guideId#pageId`, or `guideId#pageId#anchor` for a heading
  - Immersive Engineering: `entryId`
  - Actually Additions: `entryId`, within book `actuallyadditions:booklet`
- Parse targets strictly: every ResourceLocation part must round-trip through `ResourceLocation.tryParse(part).toString().equals(part)`, and a wrong separator count is rejected.
- Navigation outcomes:
  - Outside the active scope: `STALE`.
  - Off the client thread: `UNSUPPORTED`.
  - The source handle no longer matches the destination: `STALE`.
  - Missing, hidden or locked destination, or unavailable viewer: `UNAVAILABLE`, with zero native calls.
  - Native call succeeds: `OPENED`.
  - Native call throws `RuntimeException` or `LinkageError`: `ERROR`.
- Never substitute another entry, page or anchor, and never cache native entry, page, guide or screen objects across calls.
- Keep adapter version ranges, the adapter list and build dependencies unchanged.
- No formatting tools and no unrelated edits. Commit each written step with a message generated by `$commit-message` from the staged index, without waiting for tests to pass. Never fast-forward merges.

## Review Focus

- **Resource reload between answer and click (F3+T):** the native objects are replaced. The saved link must resolve against the new content and still open. Each reader task's "recreated content" test pins this.
- **A Modonomicon entry that is locked or hidden again when clicked:** Modonomicon would open it anyway, so PackSage must refuse with `UNAVAILABLE`. Pinned in Task 2.
- **The player's language changes after a GuideME anchor link is saved:** the heading anchor may stop matching. The anchor link becomes unavailable while the page link still opens. Pinned in Task 3.
- **The IE manual fails to reload (`getGui()` returns null):** the result is `UNAVAILABLE`, with no screen set and no exception. Pinned in Task 4.
- **A resource pack removes an Actually Additions entry:** refresh returns `null` and open returns `UNAVAILABLE`, never the Patchouli `NullPointerException`. Pinned in Task 5.
