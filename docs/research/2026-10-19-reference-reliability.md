# Reference reliability

The [natural-player stress test](../validation/2026-10-18-natural-prompt-stress-test.md) reproduced two distinct failures. R3's final answer and nested-storage call changed the inventory observation ID from `07cd5168-5d6e-48b3-95ac-9f9889de7ef6` to `07cd5168-6e5d-48b3-95ac-9f9889de7ef6`. The location resolver correctly rejected that unknown reference; the same typo made the inventory citations unbound. Arc 11 instead reused an exact earlier JEI reference that was absent from the new answer's evidence selection. Neither case was a failure of the newly implemented durable destination lookup.

`NativeInventoryReader` registers exact scoped slot references and checks current scope and expiry before resolving the current location. `PackSageTools.execute` exposes provider-qualified record references and payload slot references to the model. `RequestController.toolReady` accumulates the current request's accepted evidence. `ScreenText` binds citations by exact provider and source handle. These checks correctly prevent a malformed, foreign or expired reference from selecting a different item or destination.

The model currently has to copy long transport identities into both tool arguments and prose. Prompt instructions to copy them exactly did not prevent the observed error. The correction should reduce that copying burden at the model boundary while retaining canonical provider identities and fresh-reader validation. It must not fuzzy-match a typo or silently substitute a similar item, recipe or historical source.

Any compact-reference design must account for concurrent tool completions, request isolation, bounded output, cancelled requests and restarts. Saved source details currently inspect tool-result JSON, replay validation compares submitted tool results, and steering messages and hosted citations use answer offsets. Ordinary history sends saved questions and answers without replaying their old tool results. A model-only alias must therefore have an explicit relationship to durable results and answer text; replacing strings at completion without preserving these contracts is insufficient.
