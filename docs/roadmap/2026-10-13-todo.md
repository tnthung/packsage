# PackSage feature roadmap

Updated: 2026-10-14.

Each checkbox represents one feature. Mod/framework headings and nested categories are organizational groups, not tasks. Checked items describe delivered capabilities within their stated limits; unchecked items are planned work, not compatibility claims.

Keep version-specific implementations under one logical mod ID and one adapter-status entry. A mod may need separate readers for different API/version ranges. Verify each reader's data access and supported versions before implementation; opened, held and targeted storage are separate capabilities.

## Suggested order

1. Fill observed inventory gaps: Pocket Storage display contents, Curios equipment, and specialized storage readers needed during real play.
2. Expand shared documentation coverage: Modonomicon, GuideME, then Create/Ponder.
3. Add acquisition and mechanic readers: JER, Just Enough Professions, Just Enough Breeding, then Just Enough Effect Descriptions.
4. Add narrower manuals, multiblock readers, pack scripts and alternative quest systems where the installed pack needs them.
5. Add the optional server companion for facts unavailable to a client-only reader. Features requiring server access depend on that work.

## Minecraft

- Player equipment
  - [x] Read player inventory slots.
  - [x] Read equipped armor slots.
  - [x] Read the offhand slot.
- Storage
  - [x] Read visible non-player slots from an opened standard container menu, with partial coverage.
  - [x] Read direct contents from synchronized held vanilla container components.
  - [x] Read direct contents from synchronized held bundle components.
  - [ ] Read targeted closed-container contents through authorized server access.
- Enchantments
  - [ ] Enumerate all loaded enchantment registry entries, including registered mod enchantments.
  - [ ] Read loaded enchantment maximum levels.
  - [ ] Read enchanting-power costs by enchantment level.
  - [ ] Read enchantment anvil costs.
  - [ ] Read enchantment equipment-slot requirements.
  - [ ] Read loaded enchantment effect payloads.
  - [ ] Decode built-in enchantment effect components.
  - [ ] Find enchantments applicable to a specified item under loaded eligibility rules.
  - [ ] Read incompatibility rules between enchantments.
- Status effects
  - [ ] Enumerate all registered mob-effect types, including registered mod effects.
  - [ ] Read standard effect metadata: name, category and color.
  - [ ] Read declared effect attribute modifiers.
  - [ ] Read the player's active status-effect instances, including remaining duration and amplifier.
- Potions
  - [ ] Enumerate all registered potion variants, including registered mod potions.
  - [ ] Read each potion's base effect instances, including duration and amplifier.
  - [ ] Read actual potion-item contents, including additional custom effects.
- Brewing
  - [ ] Read vanilla potion transformation mixes.
  - [ ] Read vanilla potion-container conversion mixes.
  - [ ] Read declarative NeoForge brewing recipes.
  - [ ] Decode supported custom brewing recipes through provider-specific readers.

These catalogs belong to the native Minecraft adapter. Use current registry access and item eligibility hooks; distinguish decoded common mechanics from opaque custom behavior. Brewing readers need separate access paths because the public custom-recipe list excludes vanilla mixes.
