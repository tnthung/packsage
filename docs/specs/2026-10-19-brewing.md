# Brewing evidence

Date: 2026-10-19.

Status: approved bounded design. Extend the existing [recipe contracts](2026-10-14-behavior-driven-tools.md) without new public tools or arguments.

## Behavior

- `search_recipe` includes current vanilla potion mixes, potion-container conversions and declarative NeoForge `BrewingRecipe` entries alongside ordinary native recipes. Preserve the existing literal text, output-item and provider filters and bounded live pagination.
- Read the current level's `PotionBrewing` on the client thread for every search, continuation and evidence read. References identify a transformation, never a saved record. Changed, removed or unreadable sources cannot return old evidence.
- Preserve input/output item identities and potion components. An output-item filter selects the item type and can return multiple potion variants; text can narrow the returned transformation facts.
- Read vanilla tables through narrowly checked access to the Minecraft 1.21.1 layout. Decode only the exact declarative NeoForge recipe class. Unsupported custom implementations and ingredients remain explicitly opaque, with no execution of their predicates to invent recipes.
- Preserve source ordering and custom-before-vanilla precedence as a coverage limit where overlapping rules are not fully evaluated. Client-loaded rules do not prove the effective rules of a remote server.
- Keep ingredient traversal, component encoding, transformation expansion, cursor seeking and output bounded. A page limit does not authorize an exhaustive upstream scan. Unread fields or rules cannot establish absence.

## Planning limits

Normalize supported transformations into the shared `RecipePayload` so bounded planning can use the available facts. Keep uncertain routes partial. `plan_recipe` selects an item ID and cannot select a named potion variant; retain distinct components and state that ambiguity.

One brewing operation consumes one reagent across up to three bottle slots. It consumes fuel per operation and may have ingredient remainders. Do not publish ordinary per-bottle reagent totals or exact fuel/material totals from a one-bottle transformation. Preserve the declared output stack count and describe shared batch constraints.

## Acceptance

Automated checks cover potion-component distinctions, container conversions, declarative custom entries, opaque custom implementations, bounded paging, fresh reference rereads and conservative planning. Run the focused tests and full Java 21 `test build`. Record installed acceptance separately; this change does not authorize installing or driving Minecraft.
