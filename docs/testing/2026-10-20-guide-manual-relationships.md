# Guide and manual relationship checks

Date: 2026-10-20.

Status: pending. These are installed-client checks for the candidate PackSage artifact supplied after the final automated build. They do not ask the player to run Gradle or Java. Close Minecraft before copying the supplied JAR into the test instance, verify the supplied artifact hash as directed, then launch the pack and confirm the reported Modonomicon, GuideME, and Immersive Engineering versions. Open the Immersive Engineering manual normally once if its entries are not loaded.

For each check, preserve the actual tool calls, arguments, provider/source identity, returned handle, relationship payload, coverage, fresh-read result, and assistant reply. First judge extraction: did the current source return the declared relationship with correct provenance and completeness? Separately judge answer quality: did the assistant describe only what that evidence supports? A passing extraction does not by itself establish a correct ordinary-language answer.

At least one fresh read must follow an ordinary source/progress change: for example, read a Modonomicon entry normally in the book, then reread the same returned handle. Repeat this for the source-specific change described in each check where possible.

1. **Modonomicon entry-to-item links.** Find NeoVitae's `dungeons/demon_crafting` entry and read its spotlight declarations. Record the spotlight item or ingredient identity and its source page/role. Search again with one exact returned item ID and confirm the same declared relationship is found by ID. Check an unavailable/hidden entry as a negative case: its body or relationship must not be exposed. Read the entry normally in the book, then call `read_evidence` with the original returned handle and confirm the current page relationship and source identity.

2. **GuideME page-to-item links.** Search for the exact item ID `ae2:processing_pattern`. Confirm the returned active parsed AE2 patterns page explicitly associates that item through its `item_ids` declaration. Inspect the live parsed page identity/locale in the returned provenance. After opening or otherwise normally refreshing the guide source, reread the exact returned handle and confirm current `item_ids` evidence.

3. **Modonomicon embedded recipe references.** Find NeoVitae's `utility/incense_altar` entry. Confirm the two native embedded recipe slots are returned separately with their exact recipe IDs, recipe type, and source-page positions. Search each returned recipe ID and confirm it matches the declared page reference. Do not interpret the pair as recipe execution or inferred ingredients. Open the page normally and reread its returned handle.

4. **GuideME recipe tags.** Use currently parsed AE2 guide pages. Check a direct `Recipe` tag by its literal recipe ID, the certus-growth page's `RecipeFor` target `ae2:damaged_budding_quartz`, and a live plural `RecipesFor` declaration. Confirm the payload preserves which tag supplied each reference and that `RecipeFor` and `RecipesFor` retain their native one-versus-many meanings. Verify the returned facts identify parsed live pages rather than bundled Markdown resources. Reread a returned handle after a normal guide/source refresh.

5. **Immersive Engineering manual recipe references.** In the loaded manual, inspect the hammer/wirecutter crafting references and a blueprint or bottling selector. Confirm recipe-name, output-selector, and fixed-layout forms remain distinct. Include named-potion variants and confirm their potion components remain distinguishable. If the installed manual does not contain a fixed-layout or fluid-selector declaration, leave that subcase pending fixture preparation. The required in-game fixture must declare `ManualRecipeRef(PositionedItemStack[])` entries with `displayList`, `x`, `y`, and `amount` for fixed layout, and a `ManualElementMixer` entry with a native fluid selector. Java test fixtures do not establish installed runtime proof. Reread the returned handle after a normal manual/source update; tool use must not open or reload the manual itself.

6. **Modonomicon prerequisites.** Inspect NeoVitae's `alchemy_arrays/crafting_array` with parent/read prerequisite `alchemy_arrays/arcane_ash`. Check that the graph-parent edge, native entry condition tree, and current display/unlock state are separate evidence. Confirm locked-but-visible declarations can be reported while hidden entries and locked page bodies remain unavailable. Custom conditions may remain explicitly opaque; do not accept a complete explanation inferred from the parent edge alone. Read the entry normally and reread the original returned handle.

**Existing text-search regression.** Search Immersive Engineering's introduction using the known literal `Greetings and welcome` after the manual is open. Confirm ordinary text matching and a fresh evidence read still work alongside relationship matching.

**Record results.** Mark each check as extraction pass/fail and answer-quality pass/fail independently. Keep the corresponding roadmap box open until both automated checks and installed extraction acceptance are recorded. Report unresolved source visibility, custom-condition opacity, or unavailable page variants in the validation record; do not turn those limits into unsupported absence claims.
