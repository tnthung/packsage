# Task 8 config bridge validation

The pinned runtime is NeoForge 21.1.202 with FML loader 4.0.41. The bridge checks both versions before reading `ConfigTracker.INSTANCE`, then reads the tracker catalog through its bounded internal fields. It calls the public `ModConfig` getters and invokes `config()` through the public `IConfigSpec.ILoadedConfig` interface, because the concrete FML `LoadedConfig` implementation is package-private in FML 4.0.41. A failed entry extraction or catalog bound marks the bridge unsupported and retains any successfully copied entries for partial file-backed inspection.

Loaded values and metadata are copied into immutable `Entry` and `Value` snapshots before they leave the client capture executor. Arrays and opaque values become bounded immutable representations, and cyclic or oversized containers receive an omission marker. `ConfigProvider.production(...)` captures that catalog on the supplied client executor and performs approved-root file enumeration and TOML parsing on the supplied worker executor. The provider never calls config setters, save or reload operations. Missing, invalid or unreadable known roots produce partial coverage even when they yield no files; accessible empty roots remain complete-empty. When the bridge is unsupported or a catalog entry is absent, bounded `.toml` files under the known roots remain available with an unknown loaded state and an explicit partial coverage label, without inferring synchronized-server identity from a filename.

Saved observations distinguish observed, partial and unknown states. The parser bounds file bytes and keys, handles scalar values, comments, dotted or quoted keys and arrays, and reports malformed, unterminated or unbalanced values, array-of-table, oversized, non-UTF-8 or unreadable files as partial/unknown evidence instead of complete evidence. Paths are normalized, real-path checked and rejected when they escape the known roots. Fallback traversal consumes at most the bounded file candidate count before materializing entries. Filtered cursors advance over the scanned catalog positions so skipped records cannot repeat.

Focused scratch validation used JDK 21 `javac` and JUnit 5.11.3 directly, without Gradle or formatting tools. `ConfigProviderTest` passed all 17 tests, including the exact pinned reflective bridge, saved-versus-loaded labels, filtered pagination, malformed quoted/unbalanced values, oversized/non-UTF-8 files, missing/invalid versus accessible empty roots, immutable opaque/array/cyclic snapshots, bounded fallback traversal, unsupported-catalog file fallback, bounded catalog values and client-capture/worker-parse separation. Live G2 saved-versus-loaded and synchronized-server checks remain pending.
