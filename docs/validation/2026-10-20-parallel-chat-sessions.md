## Decisions during execution

- Backend work and store/contracts work run in parallel, followed by runtime and screen work with disjoint ownership. The parent serializes Git and Gradle. Incorrect interface assumptions would require integration rework.
- The user's SDD execution authorizes commits inside the feature worktree, superseding the earlier planning-only hold. The original checkout remains separate; merge and push are not authorized.
- Displaying a completed foreign-world conversation may acknowledge its unread UI metadata. It remains read-only for new model requests and retains navigation restrictions. A different interpretation would change acknowledgement policy without changing game authority.
- Backend cancellation retains its existing weak callback contract. A terminal event accepted before an account transition may still reach the consumer afterward; this window predates the exchange-set change. Every affected runtime holder must invalidate before the backend account transition, and generation guards must reject late effects. Incorrect ordering could allow stale answers or notices.
- The start-latch test did not force the private account-epoch snapshot/registration interval, so it was replaced with deterministic cleanup/account-replacement coverage. Retained per-request consumers provide the runtime's late-event test seam. The backend epoch-registration check remains; no callback-drain framework or test-only production hook is added. The narrow internal interval has no forced-interleaving test.
- The dot uses existing draw geometry without a geometry-only test seam. Headless checks cover row state, narration and controls; exact visible alignment remains Minecraft acceptance.
- Read-attempt deduplication belongs to the runtime. The screen's void action may repeat while a marker remains; failed persistence keeps the marker and can retry on explicit reopen without disk writes every frame. Incorrect attempt identity could prevent a retry or cause redundant writes, so runtime checks cover that boundary.
- Adopt one claimed future for holder initialization, with factory/provider/controller calls and future completion outside runtime locks. Load generations must reject stale work before attachment, and call sites continue without blocking. A Sol architecture review resolved the conflict between one controller authority and the original initialization monitor; incorrect ownership or guards could strand loading state or attach stale conversations. The decision retains the existing executor contract without assuming every public caller is serialized.

- Fence reserved sends with a fresh atomic admission token, revoked by lifecycle changes or selected Stop and checked inside controller activation. Cleanup must match that token, and immediate cancellation must have safe target/evidence state. The architecture review specified this after tests reproduced a post-transition backend start, a null-target cancellation and a surviving late capture. Incorrect ordering could admit old-world work or corrupt a newer request; selection alone does not cancel and the weak callback contract remains unchanged.

- Permit local test-only reflection to replay captured views and the private reconciliation/completion phases and authority fields needed for deterministic interleavings. There is no public injectable publication seam; a production hook or factory would enlarge this feature. Tests remain coupled to those private shapes and may need maintenance when they move, while real completion/read persistence supplies the observable assertions.
- Treat publications as wakeups and reconcile a fresh controller view outside runtime locks using a holder-local ticket and the unread identity captured before the read. Protect pending replacement metadata and reservation-owned starting state. A fresh read alone can be overtaken; incorrect guards could erase a newer completion or overwrite/strand activity. Verification requires delayed publication/read, replacement and reservation/settlement regressions for this bounded protocol.
